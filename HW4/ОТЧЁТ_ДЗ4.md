# Домашнее задание № 4

## Улучшение и защита банковского TCP-сервера, логирование, Docker, semgrep

## 1. Цель и условия

В ДЗ № 3 анализировался банковский сервер. Зафиксированы шесть срабатываний Semgrep: использование алгоритма MD5 для хеширования паролей и искусственная задержка time.sleep (Race Condition). Изучены 12 attack-скриптов, демонстрирующих уязвимости: SQL-инъекции, IDOR, Replay-атаки и DoS.

**Цель:** доработать сервер из ДЗ-3 — устранить уязвимости, выявленные semgrep и
демонстрационными атаками, добавить логирование, запустить сервер в Docker и
повторно проверить код и Dockerfile инструментом semgrep.

| Параметр            | Значение                                              |
| ------------------- | ----------------------------------------------------- |
| Среда               | Windows + WSL (Ubuntu), Docker                        |
| Язык / зависимости  | Python 3.13, pydantic                                 |
| Объект              | `main_secure.py` (доработанный сервер) + `Dockerfile` |
| Инструмент проверки | Semgrep (наборы `python` и `dockerfile`)              |
| Автотесты           | `test_security.py` — 12 проверок, все проходят        |

## 2. Соответствие «фикс → закрытая атака»

| Уязвимость (ДЗ-3)               | Исправление                                            | Атака                                  |
| ------------------------------- | ------------------------------------------------------ | -------------------------------------- |
| MD5 для паролей                 | PBKDF2-HMAC-SHA256 + соль                              | слабый хэш, брутфорс                   |
| `time.sleep` в переводе         | удалена                                                | race condition                         |
| SQL-инъекция при входе          | вход без SQL: поиск пользователя + сравнение хэшей     | `attack_sqli.py`                       |
| Произвольный `ADMIN <sql>`      | только `ADMIN LIST_USERS`                              | `attack_admin_sql.py`                  |
| `HISTORY <чужой id>`            | только своя история                                    | `attack_idor.py`                       |
| Отрицательная сумма             | `amount > 0` (валидация pydantic)                      | `attack_negative_transfer.py`          |
| Перевод себе                    | запрет `to_id == id`                                   | `attack_self_transfer.py`              |
| Гонка (TOCTOU)                  | `threading.Lock` на перевод                            | `attack_race.py`                       |
| Replay                          | одноразовый `request_id`                               | `attack_replay.py`                     |
| Брутфорс                        | блокировка после 5 неудач на 60 с                      | `attack_bruteforce.py`                 |
| DoS / Slowloris                 | абсолютный дедлайн на чтение строки + лимит соединений | `attack_dos.py`, `attack_slowloris.py` |
| Подмена `bank_db.json`          | атомарная запись + права `0600`                        | `attack_tamper_db.py`                  |
| Кривые / слишком длинные данные | строгая валидация + лимит длины строки                 | `attack_fuzz.py`                       |

## 3. Логирование

Используется стандартный модуль `logging`, вывод в stdout (виден через
`docker logs`). Логируются подключения, успешные и неудачные входы с IP,
блокировки, переводы, отклонённые атаки и ошибки. Пароли не логируются.

Пример журнала (фрагмент):

2026-10-28 21:49:32 | INFO | Secure banking server listening on 0.0.0.0:9999
2026-10-28 21:49:33 | INFO | LOGIN ok: login=alice ip=127.0.0.1
2026-10-28 21:49:33 | WARNING | LOGIN fail: login=' ip=127.0.0.1
2026-10-28 21:49:33 | WARNING | SELF-TRANSFER rejected: user=alice
2026-10-28 21:49:33 | WARNING | REPLAY rejected: user=alice req_id=REQ9
2026-10-28 21:49:34 | WARNING | LOCKOUT: login=alice after 5 fails

## 5. Запуск через Docker

Сервер упакован в контейнер (`Dockerfile`, `docker-compose.yml`). Ключевое для
безопасности: образ закреплён по хэшу, запуск под непривилегированным
пользователем (`USER appuser`, не root), `read_only`, `cap_drop: [ALL]`,
ограничения ресурсов (`mem_limit`, `cpus`, `pids_limit`).

Команды запуска:

​`bash
docker compose up --build -d     # собрать и запустить
docker ps                        # состояние контейнера
docker logs secure-bank          # журнал приложения
docker compose down              # остановить
​`
